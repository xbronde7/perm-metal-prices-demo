# Металл.Пермь — закупки и материалы

Собственный веб-интерфейс и Python-сборщик открытых закупок, прайсов и складских справок. Пользователю нужен только браузер.

Рабочий раздел: https://xbronde7.github.io/perm-metal-prices-demo/#deals

## Что делает текущая версия

1. Собирает открытые региональные закупки из подключённых лент B2B-Center.
2. Извлекает позиции, количества, сроки и документы, когда источник публикует их без входа; следует на первичную площадку закупки и её публичную страницу документов.
3. Обходит реестр поставщиков и найденные ссылки на прайсы/каталоги/остатки.
4. Читает XLS, XLSX, CSV, HTML-таблицы, JSON-LD, XML/YML, таблицы PDF и DOCX.
5. Сопоставляет материалы по типу, размерам, марке, классу, исполнению и указанным ГОСТам. Jev выбирает ссылки и оценивает пары; противоречия характеристик отсекаются правилами.
6. Сохраняет исходные файлы по SHA-256, историю изменений и последний успешный срез. Ошибки источников показаны в интерфейсе.
7. Показывает закупки, предложения, складские количества и ссылки на доказательства. CSV по закупке открывается в Excel.

## Архитектура

```text
Ленты закупок / документы → позиции потребности
Реестр поставщиков → обход сайтов → прайсы / каталоги / складские справки
                 ↓                 ↓
            нормализация характеристик и единиц
                 ↓
   правила совпадения + дополнительная оценка Jev
                 ↓
 SQLite + исходные документы → deals.json → React/Vite → браузер
```

- `collector/scripts/radar/transport.py`: доступ к публичным HTTP(S)-источникам, robots.txt, лимиты, архив оригиналов.
- `documents.py`, `procurement.py`: извлечение предложений и потребностей.
- `domain.py`: единицы, марки, размеры, ГОСТы, строгие конфликты.
- `jev.py`: ограниченные запросы TypeSafe; ключ остаётся на сборщике.
- `pipeline.py`: постоянное состояние, история, сбор, сопоставление и экспорт.
- `run_radar.py`: разовый запуск или сервер с расписанием и API оператора.
- `web/`: независимый интерфейс; сохранены сравнение цен и остальные страницы.
- `.github/workflows/radar.yml`: сбор и публикация каждые 4 часа, ручной запуск из Actions.

## Работа опубликованной версии

GitHub Actions выполняет сбор при закрытом браузере и публикует новый срез на GitHub Pages. Расписание — каждые 4 часа, на 17-й минуте; GitHub может задерживать запуски. SQLite и исходные файлы сохраняются между запусками в Actions Cache, который может быть вытеснен; для гарантированного архива используйте постоянный сервер и резервные копии.

Секрет `TYPESAFE_API_KEY` хранится в настройках репозитория Actions. `SEARXNG_URL` — необязательный секрет адреса собственного поискового сервера. Без него новые сайты берутся из отраслевого реестра, а полнота поиска в интернете не заявляется. Кнопка «Обновить список» перечитывает опубликованный срез; сбор запускается расписанием или через Actions. На собственном сервере дополнительно доступна кнопка запуска сбора.

## Настройка области сбора

`collector/radar.config.json` задаёт ленты, поставщиков, отраслевые реестры, лимиты обхода и допустимый возраст цен. Начальные компании из `data/snapshot.json` имеют региональную привязку. Новые сайты из реестра и поиска проходят проверку региона; национальный прайс не считается ценой пермского склада автоматически.

Текущие ограничения одного цикла: до 25 закупок, 12 детальных карточек, 24 сайтов поставщиков, 3 страниц на сайт, 180 HTTP-запросов и 25 вызовов Jev. Расширяйте лимиты и подключайте отдельные адаптеры под конкретные площадки. Учитывайте лимиты источника и частоту обновлений.

КВИН имеет отдельный адаптер матрицы цен и складской справки. В остатки берутся строки склада Перми, план будущих поставок исключён. Если единица цены не указана, она остаётся неизвестной.

## Запуск разработчиком

Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/pip install -r collector/scripts/requirements.txt
.venv/bin/python -m unittest discover -s collector/scripts/tests -v
.venv/bin/python collector/scripts/run_radar.py once --config collector/radar.config.json --snapshot data/snapshot.json --output data/deals.json --state .radar-state
cd web
npm ci
npm run check
npm run build
```

Перед сборкой скопируйте актуальные `data/*.json` в `web/public/data/`; workflow делает это автоматически. Для Jev передайте `TYPESAFE_API_KEY` через окружение либо игнорируемый файл `collector/.env.radar` с правами `0600`. Не включайте его в Git или веб-сборку.

Собственный постоянный сервер (после сборки `web/dist`):

```sh
.venv/bin/python collector/scripts/run_radar.py serve --config collector/radar.config.json --snapshot data/snapshot.json --output data/deals.json --state .radar-state --web-dir web/dist --host 127.0.0.1 --port 8787
```

Он запускает сбор сразу и затем с интервалом из конфигурации. Для доступа извне нужен HTTPS reverse proxy; внешнее связывание требует `RADAR_ADMIN_TOKEN`. Токен проверяется только при запуске сбора, ключ Jev клиенту не передаётся. Папка `.radar-state` должна находиться на постоянном диске и резервироваться.

## Границы достоверности

- Это список закупок и кандидатов на поставку. Подтверждённой прибыли текущая версия не рассчитывает.
- Отсутствующие количество, цена, единица, НДС, ГОСТ или остаток не дописываются моделью.
- Совпадение указанных характеристик не заменяет сертификат и проверку договора, срока, доставки и наличия.
- Год ГОСТ нормализуется из написания, актуальность стандарта и допустимость замены не подтверждаются автоматически.
- Тонны/килограммы и метры/километры пересчитываются размерно. Масса метра или штуки не выдумывается.
- Старые цены и предложения ниже минимальной партии не включаются в ориентировочную стоимость. Сумма по позициям с разными или неизвестными условиями НДС не считается.
- Если документация требует входа, JavaScript API или OCR скана, карточка показывает необходимость спецификации/адаптера. Обход ограничений доступа не выполняется.
- Подключены выбранные источники, а не все площадки и сайты Пермского края. Полнота реестра и актуальность остатков требуют отдельной проверки.
